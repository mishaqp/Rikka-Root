# SAF, клавиатура и раздел «Интерфейс» после fb4fe00f

Проверка начата 13.10.2026 в ветке `ccr-e93188a6-grrqko`, поверх `fb4fe00f`. Прочитан `AGENTS.md`. APK собирается только через Daily Build; публикация — одним push после всех локальных проверок. Спецдоступы и разрешения Android не меняются.

**Точный класс исключения `copy_file` на POCO пока неизвестен.** Старый запасной текст не содержит этой информации. В этой версии `copy_file` уже использует создание документа и потоковое копирование; `DocumentsContract.copyDocument` и `moveDocument` не вызываются. Поэтому неподдержку native-copy нельзя объявить причиной телефонного сбоя.

Реалистичный тестовый `DocumentsProvider` выдаёт настоящий `ParcelFileDescriptor`, сохраняет файлы на диске и повторяет существенные особенности ExternalStorageProvider: отсутствие поддержки COPY/MOVE, `createDocument` с новым documentId и уникальным именем при столкновении, открытие `r`/`wt`, ошибки потоков и удаления. Проверяются настоящие инструменты и JSON-ответы, а не только вспомогательная функция копирования. На исходном `fb4fe00f` обычная копия и ZIP только из существующего файла в новый путь уже прошли эти проверки на API 28 и 35. Это подтверждает работу проверенного пути, но не доказывает работу конкретного OEM-провайдера на телефоне.

В описании телефонной проверки успешное удаление `rikka_new.txt` указано перед копированием этого же файла. Если порядок буквальный, источник перед новой проверкой нужно создать снова. Само отсутствие источника обычно даёт другую русскую ошибку; его нельзя считать доказанной причиной старого общего текста.

Приоритет исправлений: высокий — сохранность файлов при перемещении/откате и сокрытие сообщений провайдера; средний — совместимость массовой копии, диагностика, фокус клавиатуры и потеря вводимых символов; обычный — активация пользовательской темы. После обновления на телефоне:

1. Снова создать источник; выполнить copy в новый путь и прочитать содержимое копии. Проверить отказ замены без overwrite и замену с overwrite.
2. Проверить ZIP только из существующего источника в новый путь, затем move и batch_copy внутри выданного Download.
3. Если copy снова упадёт, сразу вызвать `generate_bug_report` и сохранить его ZIP **до следующей неудачной файловой операции и перезапуска**: `file-operations.txt` покажет исходный класс. Последующая ошибка `zip_files` заменит эту запись. Не удалять источник до проверки копии.
4. Несколько раз открыть/закрыть drawer: клавиатура появляется только после нажатия поиска, после закрытия исчезает. Проверить обычный ввод в чате.
5. В числовых настройках ввести значение и нажать «Готово»: значение сохраняется, клавиатура закрывается.
6. Быстро ввести имя и эмодзи профиля, выйти и вернуться: последние символы сохраняются. При включённых динамических цветах создать и импортировать тему: должна примениться её палитра.

Предложения по улучшению: точную OEM-причину копирования и физическую работу IME можно подтвердить только повтором на POCO. Нативные COPY/MOVE или изменение безопасности без такого доказательства не предлагаются как исправление.
