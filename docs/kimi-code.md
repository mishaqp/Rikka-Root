# Вход в Kimi Code

Цель: встроенный провайдер Kimi Code с входом через официальный браузерный device-code OAuth, постоянной сессией, автоматическим обновлением токенов и использованием моделей аккаунта в существующем чате и инструментах.

Основа протокола: официальный MoonshotAI/kimi-code, commit `7ccac2b45b8a3481c76f771bb99c043b562de2c5`, `packages/oauth`. Реализация для Android самостоятельная; API Codex и существующие ссылки сохраняются.

## Поведение

- В настройках провайдеров появляется «Kimi Code». Выбор региона: Kimi.com (Китай) или Kimi.ai (международный).
- «Войти в Kimi» запрашивает код устройства, показывает код и открывает официальную страницу в системном браузере. Пароль вводится только на стороне Kimi.
- На время подтверждения используется существующая foreground-служба OAuth с отдельной сессией; завершение, отказ и отмена освобождают её. Новые разрешения не добавляются.
- Ожидание учитывает срок кода, интервал polling и `slow_down`; допускает отмену и сетевые сбои. Успех означает получение и сохранение токенов; доступность моделей проверяется отдельно.
- Сессия загружается до первого запроса, хранится AES-GCM с отдельным ключом AndroidKeyStore в `noBackupFilesDir`. Токены не входят в настройки, бэкапы и журналы запросов.
- Обновление сессии сериализовано и принадлежит приложению: отмена ожидающего запроса не теряет уже выданный токен. Ротация refresh-токена сохраняется атомарно; временная ошибка не удаляет аккаунт. Logout и повторный вход защищены от позднего ответа старой операции.
- Чат использует существующий потоковый транспорт OpenAI/Anthropic с реальными tools, reasoning и статистикой. Модели и возможности берутся из каталога аккаунта; настройки и идентификаторы уже выбранных моделей сохраняются при обновлении.
- Пользователь видит состояние аккаунта, подписку и доступные квоты. Метаданные не блокируются исчерпанием квоты генерации.
- Клиент сообщает собственное имя Rikka-Root, не подменяет идентичность официального CLI.

## Границы проверки

Официальная инструкция Kimi для сторонних клиентов документирует API-ключи; поддержка device OAuth собственным Android-клиентом требует проверки с реальным аккаунтом на телефоне. Автоматические проверки используют контролируемый HTTP и не запрашивают личные токены пользователя. Успешный OAuth не обещает доступ к моделям вне подписки.

Сборка и полные проверки выполняются только workflow Daily Build; подпись и applicationId сохраняются.

## Как пользоваться

1. Настройки → Провайдеры → Kimi Code.
2. Выберите Kimi.com либо Kimi.ai согласно сайту, на котором действует подписка.
3. Нажмите «Войти в Kimi», подтвердите вход в браузере и вернитесь в приложение.
4. Дождитесь проверки моделей. При первом успешном получении каталога Kimi включается, а первая доступная модель выбирается для новых чатов. Существующие чаты сохраняют свой выбор.
5. При необходимости выберите модель во вкладке моделей или в чате. «Проверить аккаунт и обновить модели» обновляет каталог, профиль и квоты; «Выйти из Kimi» удаляет сессию с устройства.

Временный сбой сервера не удаляет сессию. Неподдерживаемый протокол, ошибка подписки, отказ доступа и оборванный поток возвращаются как ошибки. При гибели процесса во время ещё не подтверждённого входа начните вход заново; уже сохранённая сессия восстанавливается автоматически.

## Ошибки HTTP 400 и K3.1 Pro

HTTP 400 означает, что Kimi получил и отклонил запрос. Такой ответ показывается как ошибка провайдера с описанием причины, а не как потеря сети; автоматические сетевые повторы к нему не применяются. Настоящие ошибки DNS и соединения сохраняют прежний механизм повторов. Для диагностики читается не больше 16 КиБ JSON-ответа, показывается не больше 2048 символов поля ошибки; OAuth-токены и другие распознаваемые секреты удаляются. Ошибки авторизации по-прежнему не отражают произвольный ответ сервера.

По [контракту Kimi](https://www.kimi.com/code/docs/en/kimi-code/models.html), `k3.1-pro` и `k3.1-pro-highspeed` требуют рассуждений. Для этих ID они остаются включёнными даже при старом или неполном каталоге и сохранённом значении «выключено» в чате. При отсутствии метаданных используются документированные уровни `low` / `high` / `max` и значение по умолчанию `max`; явно объявленные каталогом допустимые значения сохраняют приоритет.

В Chat Completions включённое рассуждение требует поля `reasoning_content` у сообщений ассистента с вызовами инструментов. Уже полученный текст сохраняется, а отсутствующее поле передаётся явно пустым. Текст рассуждения не придумывается; аргументы инструментов и команды не меняются.

Код 400 сам по себе не устанавливает причину: Kimi также возвращает его при неверных параметрах, превышении размера/контекста и других отказах. Для конкретного случая нужен текст причины из ответа сервера.

## Проверка на телефоне

- Войти с реальной подпиской для своего региона, проверить настоящее получение моделей и ответа.
- Свернуть приложение в браузер, подтвердить вход, вернуться; повернуть экран во время ожидания и проверить отмену. Уведомление OAuth должно исчезнуть после завершения.
- Полностью закрыть и открыть приложение после успешного входа: сообщение отправляется без повторной авторизации.
- Проверить потоковый текст, рассуждения и вызов безопасного инструмента, затем продолжение после результата инструмента.
- Проверить поддерживаемое моделью изображение, обновление каталога/квот и выход/повторный вход. Недоступные модели и квоты не должны отображаться как успешная генерация.
- Убедиться, что прежний Codex, старые чаты и мини-приложения работают после установки подписанного nightly.
