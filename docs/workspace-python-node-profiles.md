# Профили Python и Node.js в рабочих папках

## Область действия

Профиль принадлежит одной рабочей папке и выполняется только внутри её Rootfs. Android, Root, Termux, другие рабочие папки и файлы проектов не изменяются. Состояние хранится в метаданных рабочей папки в `.workspace-profiles.json`, а не в `/workspace` или `.venv`.

Поддерживаются Rootfs с точным `ID=ubuntu` или `ID=debian` в `os-release`; `ID_LIKE` сам по себе поддержку не даёт. Для остальных дистрибутивов отображается «Дистрибутив пока не поддерживается», а `apt` не запускается. Основной проект по умолчанию использует Ubuntu 24.04.

Если Rootfs отсутствует или повреждён, интерфейс предлагает существующую установку/восстановление Linux. Rootfs автоматически не переустанавливается. Общий `apt-get upgrade` и `dist-upgrade` не используются.

## Подготовка и источники

Перед установкой выполняется полная функциональная проверка существующего окружения. Исправное окружение используется повторно, без переустановки и без скачивания.

Python устанавливается из штатных репозиториев дистрибутива:

```sh
apt-get update
apt-get install -y --no-install-recommends python3 python3-venv python3-pip
```

Для Node.js допускается существующая поддерживаемая LTS major 22 или 24 с npm. Если её нет, после проверки архитектуры используется официальная фиксированная сборка **Node.js v24.22.1 (LTS Krypton), npm 11.19.1**. Перед распаковкой скачиваются `ca-certificates` и `xz-utils` из штатных репозиториев.

Официальные источники Node.js:

- метаданные релизов: `https://nodejs.org/dist/index.json`;
- контрольные суммы: `https://nodejs.org/dist/v24.22.1/SHASUMS256.txt`;
- arm64: `https://nodejs.org/dist/v24.22.1/node-v24.22.1-linux-arm64.tar.xz`;
- x64: `https://nodejs.org/dist/v24.22.1/node-v24.22.1-linux-x64.tar.xz`.

Закреплённые SHA-256:

- arm64: `dbabf7a1cbf947e6059ffad2c27b80041db97dea1e553b62afdee7f13fca336e`;
- x64: `6c172a9ab6718f7b801fb5a7bd486af2ee5e32758086a04b84fcce2aa77095e6`.

Хеш сверяется и с официальным `SHASUMS256.txt`, и с фактически скачанным архивом. Несовпадение останавливает операцию до `apt` и распаковки. Архив удаляется после операции. Используются прямые HTTPS-файлы, а не непрозрачные `curl | bash` установщики.

Отдельная сборка размещается в `/opt/rikkahub/node-v24.22.1`. Изменяются только app-owned staging/backup-каталоги этой сборки. Существующие `.venv` и файлы проектов не перезаписываются.

## Критерии «Готово»

«Готово» присваивается только после успешных функциональных проверок:

- Python: версия `python3`, JSON и UTF-8, системный pip, создание временного venv, запуск его Python и `python -m pip`;
- Node.js: Node и npm с версиями, JavaScript с JSON и записью/чтением файла, поддерживаемый major 22/24.

Временные проверочные каталоги создаются через `mktemp` внутри Rootfs `/tmp` и удаляются через `trap`. Кнопка «Проверить» выполняет только локальные команды проверки: она ничего не скачивает и не переустанавливает профиль.

В настройках отображаются фактические состояние, версии, пути запуска, `exit_code`, причина ошибки и раскрываемая диагностика. Во время операции показывается недетерминированный индикатор без выдуманного процента.

## Команды для проектов

Активация venv не сохраняется между отдельными вызовами `workspace_shell`. Используйте явные пути:

```sh
/workspace/<проект>/.venv/bin/python
/workspace/<проект>/.venv/bin/python -m pip install ...
```

Для Node.js зависимости устанавливаются локально: `npm install` в каталоге проекта. `npm install -g` и изменение Root PATH запрещены. Для отдельной сборки PATH задаётся только одной команде:

```sh
PATH=/opt/rikkahub/node-v24.22.1/bin:$PATH <команда>
```

## Операции, отмена и восстановление

В одной рабочей папке одновременно допускается только одна операция профиля; повторное нажатие не создаёт дубликат. Разные рабочие папки независимы. Операции принадлежат application-scope и не перезапускаются при повороте экрана или повторном открытии страницы.

Блокирующие скачивание, установка и файловые операции выполняются вне главного потока. «Остановить» отменяет только принадлежащий Job и его foreground PRoot/скачивание через `runInterruptible`; `stopBackground` и посторонние процессы не затрагиваются.

После гибели приложения сохранённые «Подготовка»/«Проверка» переводятся в «Прервано». Автоматически выполняется только повторная проверка, установка не возобновляется.

Generation marker и fingerprint Rootfs не дают сохранить устаревшее «Готово» после замены, восстановления или удаления Rootfs, в том числе во время проверки. Установка Rootfs сбрасывает метаданные профилей.

## Данные для модели

`WorkspaceReminderTransformer` использует workspace эффективного assistant текущего разговора, который формируется с учётом `ConversationConfig`. Модели передаются только компактные фактические состояние, версии и пути Python/Node/npm, а также правила локальных зависимостей. Диагностика, `rootfsStamp`, env, ключи и секреты не передаются.
