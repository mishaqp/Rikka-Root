## Среда проверки

- После повторного запуска облачной среды потребовалась холодная компиляция.
- Новые тестовые harness сначала имели ошибки импортов/Java generic-вызова. Они исправлены; такие падения не считались RED приложения.
- Robolectric child JVM не наследовал прокси Gradle и получал `UnknownHostException` для SDK 28/35. Runtime-артефакты загружены через штатный прокси и проверены SHA-512, прокси передан тестам через локальный `~/.gradle/init.d`.
- Попытка использовать Google Maven mirror дала HTTP 503 до тестов; исходные Gradle repositories восстановлены. Настройки репозитория и CI не менялись, тесты не отключались. Новая Maven 429 пока не наблюдалась.
- GitHub API некоторое время возвращал HTTP 503; затем доступ восстановился. Старый Actions run не считается результатом этой задачи. Загрузка старого artifact через Azure blob недоступна (Forbidden); текущие проверки выполняются локально и в новой сборке.
- Параллельных запусков Gradle нет; общая блокировка, два локальных worker и ограничение Kotlin 2GiB. Изменения среды не входят в приложение.

## Что осталось и почему

Причину запрета/задержки запуска браузера на POCO Android 16 / HyperOS нельзя доказать Robolectric. Теперь отчёт различает отсутствие `onCreate`, незавершённое создание WebView, отсутствие bind и уничтожение окна. Таймаут, доступы и поведение безопасности не менялись.

Реальные IME/GPU/OEM, голос, WebView/HTML/Mermaid, системный медиасканер и выполнение Root/Termux/SSH требуют телефона. Не добавлены отсутствующие backend-данные Moru (stdout/revisions), мини-карта или внешнее окно. Это выходило бы за исправления переноса и заданные границы. Спецдоступы Android не добавлялись.

Снимки `browser_screen`, `workspace_files`, `workspace_shell` показывают чат и входы в инструменты, а не настоящий BrowserActivity/отдельные окна файлов и терминала. Переходы проверены настоящими callbacks/intents; успешную работу этих окон на телефоне PNG не доказывают. Свёрнутые legacy-сцены и неподвижные кадры не доказывают доступность скрытых длинных JSON/результатов или отсутствие мерцания GPU.

Плавающая навигация справа может временно наложиться на край действий сообщения — это существующий способ размещения как в Moru. В SCROLL панель исчезает через 1500 мс, в ALWAYS остаётся до смены позиции списка; по статическому кадру центр «Ещё» может попасть под кнопку прокрутки. Режимы, координаты пользователя и ширины сообщений вслепую не менялись: резервирование отдельной полосы потребовало бы изменения общей раскладки. План отдельной доводки — сначала физический touch-тест по центру «Ещё» (semantics `performClick` не проверяет перехват), затем выбор размещения, которое сохраняет пользовательские координаты и все действия. Это ограничение честно оставлено в отчёте, а не объявлено исправленным.

## Короткая проверка на телефоне

1. Обновить APK; открыть 320dp/крупный шрифт, четыре темы, обои; прокрутить под шапкой и вводом.
2. В открытом чате поменять включение/шаг прокрутки кнопками громкости и проверить без перезапуска.
3. Выбор нескольких чатов: поиск → удалить/отмена → в папку/отмена; закрыть меню с открытым диалогом.
4. Нажать источник оригинала и перевода; проверить вставку/отправку подсказок, модель, действия и версии сообщений.
5. Через выданный Download создать новый текст/двоичный файл, копию и ZIP по полному пути; существующий файл без overwrite должен сохраниться.
6. Браузер: ручное открытие и `browser_open` в том же чате при открытом приложении, затем в фоне. При ошибке сразу создать ZIP отчёта; нужен `browser-lifecycle.txt`, версия Android System WebView и точное время попытки.
7. Сохранить настройки, перезапустить приложение и восстановить старый бэкап с обоями/шрифтами.
8. Крупный шрифт: очередь читается, редактирование/удаление/возобновление работают. Проверить «Ещё» рядом с плавающей правой навигацией в SCROLL и ALWAYS.
