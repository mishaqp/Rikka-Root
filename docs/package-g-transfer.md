# Пакет G и согласованные исправления F

Исходник: ExTV/rikkahub-agent, commit `a88f5854`; база Rikka-Root: `650b2515`, upstream 2.5.6. Один первоначальный push в `ccr-e93188a6-grrqko`; отдельные коммиты по подсистемам. Большой объём согласован пользователем для этого выпуска.

## Выполнено

- KeyRoulette: вместо открытых ключей — SHA-256 отпечатки; старый cache мигрирует при запуске с сохранением LRU/провайдера/срока, исходный plaintext-файл удаляется.
- MCP: старые headers и OAuth clientSecret/accessToken/refreshToken переносятся в AES-GCM vault AndroidKeyStore до первого чтения настроек; обычная запись и восстановление защищены тем же путём. Отказ Keystore не публикует открытые данные. Сохранение защищённых настроек сериализовано с вычислением update(fn), чтобы две одновременные правки не теряли друг друга. Старый пользовательский ZIP не изменяется; новый бэкап содержит ссылки, не секреты.
- ProviderMetadata: одна итоговая строка на HTTP-ответ, в том числе SSE/отмена/ошибка: provider, model, http_code, event_count, size_bytes, duration_ms. Тексты запросов, ответов и событий не логируются.
- Browser: исходная навигация, чтение, настройки и необходимые адаптации к текущему чату/разрешениям. Действия записи требуют подтверждения каждого вызова, включая YOLO/Always; в headless такие действия блокируются. Веб-контент сохраняет отметку «Спрашивать после веб-контента».
- Skills: исходные импортеры URL/text/ZIP/каталог, JS runtime, UI/тестер и все default-skills с комплектными библиотеками. Только agent-core/autonomous-agent переписаны под реальные Root-инструменты. Установка из чата меняет навыки текущего ConversationConfig; headless установка запрещена.
- JS: отдельный постоянный профиль на canonical-корень каждого навыка, изолированный от браузерных cookies и других навыков; HTTPS origin-bound bridge принимает только основной фрейм. Нужны WebView MULTI_PROFILE/WEB_MESSAGE_LISTENER; при отсутствии — понятная ошибка обновления, без общего профиля. Секреты навыков — AndroidKeyStore, без plaintext fallback.
- Screen automation: исходные 11 имён/схем на root input/screencap/uiautomator через существующий RootShellManager; команды проверяются HARDLINE и текущими правами перед каждым запуском. Shizuku/Accessibility не подключены.
- Workflows: исходные модели, семь инструментов, триггеры, условия, engine/UI; отдельная Room БД workflows.db включена в существующий backup/restore. Модель не выбирает владельца: доверенный caller и ConversationConfig, текущие права/HARDLINE через HeadlessTaskRunner, отдельный side-context. Вложенные SSH/MCP аргументы защищаются перед Room/FTS/экспортом; восстановление переписывает БД через VACUUM INTO, чтобы старые открытые ключи не оставались в свободных страницах SQLite. Сценарий без чата сохраняет веб-отметку между действиями.

## Браузер: исключения пользователя

Стандартная авторизация сохраняется как в Agent. Каталог Chromium `app_webview/` исключён из cloud backup и device transfer; ручной/WebDAV/S3 ZIP никогда не включает эту папку. Исключение AndroidKeyStore относится только к стандартному хранилищу сайтов.

Не перенесены `browser_eval_js` (произвольное чтение cookies/localStorage/password), `browser_get_dom` (значения атрибутов/полей/скриптов), `browser_screenshot` (возможное изображение раскрытого пароля). Эти функции отсутствуют в factory, каталоге и настройках; старые enabled prefs их не возвращают. Просмотрщик навыка не привязывается к AI BrowserController.

Для обычного текста подготовлен фильтр: формы, поля, скрипты и скрытые элементы исключены до Mozilla Readability, raw text, ссылок и diff; известные формы секретов редактируются в JSON, сырые JS-ошибки не возвращаются. **Граница чтения обычного текста ожидает уточнения пользователя перед push**. Инструмент чтения страницы по своей природе видит текст, который сам сайт показывает. Это не автоматическая DLP-проверка произвольного веб-текста.

## Разрешения и ограничения

Новое обычное/опасное разрешение: `BLUETOOTH_CONNECT` (Android 12+) для исходных Bluetooth workflow-триггеров. Запрос только по явной кнопке при включённой функции; отказ не выдаёт доступ автоматически и не отключает manual/time workflows. Имеющиеся INTERNET, ACCESS_NETWORK_STATE/ACCESS_WIFI_STATE, RECEIVE_BOOT_COMPLETED, WAKE_LOCK используются по назначению. Новых спецдоступов нет.

Geofence и фоновые координаты, foreground app и notification-listener триггеры, условия sunrise/sunset/foreground app отключены с русским пояснением; определения можно хранить выключенными. Root screen не имеет Accessibility fallback: дополнительные дисплеи/защищённые или нестандартные UI могут быть недоступны. set_text поддерживает печатный ASCII; кириллица/Unicode отклоняются до изменения поля. Для фонового root нужен явный запуск кнопкой «Открыть root-сессию»; после перезапуска приложения открыть снова.

Все новые группы по умолчанию выключены. Само извлечение default-skills не включает навыки у ассистента. В исходном YAML boolean auto_load не распознаётся строковым accessor — включение core-навыков вручную. Несколько неосновных Agent-навыков ссылаются на отсутствующие Telegram/notification инструменты; сохранены как исходные данные и требуют ручной адаптации. Source UI не содержит экрана ввода секретов JS-навыков.

## Проверки на телефоне

1. Старые MCP: cold start, подключение с прежними заголовками/OAuth, повторный запуск, backup/restore; в новом JSON только vault refs, на другом устройстве секреты вводятся заново. В logcat по завершении каждого ответа одна ProviderMetadata строка, без stream_event/тел запросов.
2. Browser: вручную войти на сайт, закрыть/открыть приложение — вход сохраняется; включить группу и проверить доступные чтения/навигацию. В списке нет eval/DOM/screenshot; запись даже с YOLO/Always спрашивает каждый раз, headless отказывает. «Спрашивать после веб-контента» действует и после повторного открытия чата. У другого чата нет доступа к уже открытой странице.
3. Skills: отдельно включить Import/JS, URL/text install требует подтверждения и включает навык только в текущем чате. Markdown/ZIP/каталог, существующие builtin навыки. Hash/QR/mood dashboard: запуск и просмотр, storage после перезапуска и изоляция от другого навыка/браузера; неподдерживаемый WebView сообщает об обновлении. Тестер: отмена, timeout, изображения/ошибки.
4. Root screen: одобрение su, tap/swipe/long_press, дерево/поиск/click/scroll, ASCII set_text, скриншот основного экрана; отказ su и недоступный UI дают понятную ошибку. Попытка кириллицы не меняет поле. Для workflow/skill tester открыть root-сессию явно.
5. Workflows: manual и time_cron, power/battery/screen; история/условия/cooldown/daily cap. Перезагрузка, выключение группы/сценария и отзыв tool grant блокируют следующие действия. Чужой ассистент не может изменять или запускать сценарий владельца. Bluetooth запрос/отказ, неподдерживаемые триггеры объясняют причину. Бэкап/восстановление workflows, старый ZIP без workflows оставляет прежнюю БД, повреждённая БД отклоняется до замены.
