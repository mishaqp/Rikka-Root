# Длинный чат: проверка чтений истории и прокрутки

Проверка `ChatLongHistoryRuntimeTest.navigationAndScrollingDoNotRescanAll512MixedMessages`
монтирует настоящий `ChatList` с 512 сообщениями. В наборе есть текст, Markdown с кодом,
локальные картинки и карточки инструментов. Сеть, база и модель заменены границами
существующего `ChatBeforeFixture`; список, карточки и Compose остаются настоящими.

После первоначальной композиции выполняются три одинаковые серии переходов к сообщениям
48, 96, 192, 320, 448, 504. После каждого перехода часы Compose продвигаются на 1600 мс,
чтобы проверить появление и автоматическое скрытие кнопок. Счётчик `HistoryReads`
измеряет реальные обращения к узлам исходной истории; он не установлен в рабочем коде.

До исправления закрытое окно экспорта всё равно фильтровало все узлы при изменении
видимости кнопок. Контрольные числа сняты до изменения рабочего кода; XML сохранён
в `/tmp/rikka-chat-perf-baseline.xml` текущей рабочей среды:

| Величина | До исправления | После исправления |
| --- | ---: | ---: |
| Чтения истории за 18 переходов | 18 432 | 0 |
| Время трёх серий на компьютере, мс | 1687 / 712 / 642 | 973 / 489 / 441 |
| Медиана времени серии, мс | 712 | 489 |
| Процессорное время JVM по сериям, мс | 5310 / 2250 / 1810 | 3480 / 1790 / 1480 |
| Медиана процессорного времени, мс | 2250 | 1790 |
| Чтения при расчёте предупреждения, когда последний узел — ответ | 512 | 1 |

Это время тестовой нагрузки Robolectric на компьютере, а не FPS и не замер телефона.
Процессорное время учитывает потоки всего процесса JVM и может быть больше обычного
времени серии. Влияние других потоков, прогрев JVM и изменение видимой области чата
не позволяют приписать всю разницу времени одной оптимизации. Надёжная регрессия —
отсутствие полного прохода истории при прокрутке и смене видимости кнопок.

Рабочие изменения: список экспортируемых сообщений вычисляется только при открытом
экспорте; видимость навигации читается в маленькой отдельной области композиции;
проекция строк сохраняется до изменения исходных данных; поиск последнего ответа
для предупреждения о размере прекращается сразу после найденного ответа.

Два намеренных изменения вида проверяются отдельно: непрозрачная основа панели ввода
и собственная строка навигации высотой 48 dp. Реальный размер панели ввода, очереди
и клавиатуры по-прежнему измеряет `Scaffold`; список физически заканчивается над
панелью и строкой навигации. Автоматическое скрытие кнопок не меняет этот размер.
