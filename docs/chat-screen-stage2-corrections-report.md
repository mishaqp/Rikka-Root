# Правки после телефонной проверки этапа 2

## Исправления

- Удалён постоянный резерв 36dp под навигацию из `ChatListNormal`. LazyColumn занимает всю ширину, строки сообщений получают прежние 16dp с обоих краёв. Кнопки 36dp остаются overlay в родительском Box: их видимость, сторона, прозрачность, анимация и скрытие после 1500ms покоя не меняют ширину списка. Во время показа перекрытие края текста допустимо по уточнённому ТЗ.
- Подложка inline-кода строится из нативных границ его символов отдельно на каждой перенесённой строке. Горизонтальный отступ 3dp, вертикального расширения нет. Подложка ограничивается границами соседнего непробельного текста. Сохранены исходные символы, выделение, ссылки, AST/HTML Markdown и проявление новых символов при стриминге.

## Проверки

Регрессионные тесты сначала воспроизвели обе ошибки: production ChatPage сохранял лишние 36dp справа, а inline-подложка покрывала пиксели за новым пределом. Добавлены проверки реальных границ списка и пузыря/заголовка, режимов аватара, короткого и длинного текста, вложений, полной карточки инструмента и overlay с обеих сторон. Pixel-тесты inline-кода охватывают AST/HTML, 320/411dp, масштабы шрифта 1/1.3, переносы и сохранение stream fade.

Roborazzi «ПОСЛЕ» расположен в [chat-after-stage2-fixes](../app/src/test/screenshots/chat-after-stage2-fixes): 536 PNG (67 сцен × 4 темы × 2 масштаба). Светлая, тёмная, AMOLED и динамическая темы проверяются при масштабах шрифта 1/1.3. Исторические наборы BEFORE, stage1, stage1-fixes и stage2 сохранены неизменными: 1184 PNG, контроль SHA-256 и mtime.

Намеренная запись требует `-Pchat.stage2fixes.record=true`. Обычный запуск, включая глобальное `-Proborazzi.test.record=true` из Daily Build, выполняет Verify и не перезаписывает эталоны.

Итоговый локальный запуск — 102 теста, 0 failures/errors, включая Verify всех 536 снимков с глобальным CI record-флагом. Verify сохранил SHA-256 и mtime всех эталонов. Независимая проверка не выявила оставшихся замечаний. При просмотре исправлена ошибочная сцена вложений и усилены проверки наличия/границ элементов. Перенос HTML-кода использует естественные пробельные точки разрыва; три повторных записи 88 кадров совпали побайтно. Тест длинного непрерывного кода остаётся в Markdown runtime-проверках.

Правки оформляются отдельным первым коммитом. После него выполняется этап 3; оба коммита публикуются одним пакетом и проходят Daily Build.
