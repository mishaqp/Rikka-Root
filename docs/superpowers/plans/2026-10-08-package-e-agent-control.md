**Цель:** одним выпуском исправить выбор нативных архивов и подсказку ASR, затем перенести управление расходом токенов, безопасный отчёт, субагентов и задания по расписанию.

**Основание:** запрос пользователя и AGENTS.md, раздел «Rikka-Root: правила форка». Исправления и E — отдельные коммиты; один push после локальной компиляции и выбранных unit-тестов; зелёный Daily Build, проверка подписи/nightly, остановка.

- [x] Архивы: проверить цепочку Settings.getAssistantOf(conversation) → ChatToolFactory → LocalTools, точные три имени ZIP-инструментов и выключенную опцию. Усилить описание нативной работы с /workspace/относительными путями без apt; проверить реальный ZIP roundtrip с ConversationConfig workspace и cwd.
- [x] ASR: для ERROR_LANGUAGE_UNAVAILABLE (13) и ненастроенного ASR дать два способа исправления: выбрать провайдера в «Настройки» → «Служба преобразования текста в речь» → «Распознавание речи» либо скачать офлайн-модель языка в системной службе. Не менять рабочую отмену/завершение и успешный fallback.
- [x] Запустить выбранные регрессионные тесты RED/GREEN, компиляцию app; отдельный коммит без push.

## Проект E после согласования объёма

- [x] Cost guards: выключенная опция cost_guards, nullable soft/hard caps в Assistant, caller-bound check_token_usage. Считать безопасно в Long, ограничивать новые запросы и output maxTokens, прекращать продолжение при hard cap. Субагенты расходуют общий бюджет родителя. Поздние метрики провайдера могут дать превышение в пределах одного уже отправленного запроса; не обещать точную границу биллинга.
- [x] Reliability: только generate_bug_report. Экспортировать разрешённые поля версии/системы, коды ошибок и очищенные stack frames. Не включать произвольный logcat, диалоги, настройки, ключи, пароли, команды или их вывод. Тест с короткими/нетипичными секретами.
- [x] Headless: доверенный контекст запуска задаёт владельца, effective ConversationConfig, модель, разрешённые инструменты, предел шагов/времени, бюджет и происхождение веб-контента. Отсутствие UI не выдаёт права: проверять свежие YOLO/Always/допустимые grants, обязательные подтверждения и Android-доступ. Не открывать формы/разрешения автоматически. RootCommandGuard и checkpoint выполнения остаются обязательными.
- [x] Subagents: отдельный side-context, модель по model_id при dispatch, атомарное ограничение параллельности, наблюдение/отмена только владельцем. Не переключать выбранного ассистента приложения. Отмена/таймаут прекращают сам генератор, а не только ожидание.
- [x] Cron: Room с безопасной additive migration; неизменяемый идентификатор occurrence и атомарный claim предотвращают повтор побочных эффектов после прерывания. Правдивые success/failed/blocked/indeterminate outcomes; ограниченная история. WorkManager восстанавливает расписание после перезагрузки; boot receiver только переустанавливает план. Приблизительное время запуска без exact alarms. Фоновая работа ограничена допустимым временем worker.
- [x] Cron tools: schedule_job/list_jobs/get_job_history/delete_job/pause_job/resume_job/trigger_job_now. Текущий ассистент/владелец, проверка включённой функции перед каждым запуском. Прямые действия проходят ту же политику инструмента, что LLM-вызовы.
- [x] Интеграция: точные @SerialName Agent, опции выключены по умолчанию, все чтения личных данных/изменения в ToolPermissionPolicy, русские настройки и ошибки.

## Разрешения

Ожидается новое обычное RECEIVE_BOOT_COMPLETED; уведомления используют существующий POST_NOTIFICATIONS. Спецдоступы, READ_LOGS, exact alarms и исключения из оптимизации батареи не требуются. Секреты не добавляются в БД/отчёты/бэкапы.

## Проверки и выпуск

- [x] Бюджет: переполнение Long, нулевые/невалидные лимиты, stop-before-next-request, конкурентные дети и отмена.
- [x] Headless: запрещённая root-команда, обязательное подтверждение, отозванный grant/Android-доступ, веб-контент и отключение функции.
- [x] Субагенты: неизвестная/неоднозначная модель, чужой run ID, атомарная параллельность, изоляция контекста, остановка настоящей генерации.
- [x] Cron: часовой пояс/DST, reboot/catchup, process interruption без повтора побочного эффекта, лимиты запусков, отмена/ошибка/ожидание одобрения и миграция.
- [x] Отчёт: содержимое не включает переданные секреты, сообщения, настройки или произвольные логи.
- [x] Локально только затронутая компиляция и выбранные unit-тесты: финальный выбранный набор — 254 теста, 26 классов, без ошибок; после финальной правки наблюдателя настроек повторяются компиляция и выбранные тесты cron/allowlist.
- [ ] Один финальный push, CI тесты/lint, исходная подпись и nightly SHA/APK, общий отчёт и остановка после E.

## Выполнено перед отправкой

Отдельные коммиты: d16a7817 (архивы/ASR), 35015656 (cost_guards), 581980f4 (reliability), 5a924be0 (sub_agents и общий доверенный headless runtime); cron_jobs оформляется следующим коммитом. Push до готовности всего пакета не выполнялся.

Независимое ревью проверило бюджеты/отчёт, изоляцию субагентов, shell/root broker и расписания. Регрессионные проверки воспроизвели и исправили восстановление очереди между Room и WorkManager, порядок catchup/manual claim, отмену настоящего исполнения, отключение функции во время запуска и возобновление после OFF→ON без повторения уже начатых действий. Встроенный поиск родительской модели заменяется доступными внешними поисковыми инструментами в обоих видах headless-контекста. Разовая ошибка rearm не прекращает наблюдение за настройками.

Схема 27→28 проверена по экспортированным схемам и SQLite: добавлены только две новые таблицы, определения всех существующих таблиц совпадают; существующая строка workspace сохранена; открытых колонок prompt/actions/output/error-message нет. Это проверка схемы, не тест миграции на Android-устройстве.

Новое разрешение — обычное RECEIVE_BOOT_COMPLETED. Спецдоступы и dangerous permissions не добавлены. После перезапуска процесса root-задачи требуют явного открытия привилегированного сеанса кнопкой пользователя. Расписания WorkManager выполняются приблизительно, с учётом ограничений Android.
