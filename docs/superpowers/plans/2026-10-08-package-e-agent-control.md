# Исправления архивов/ASR и пакет E

**Цель:** одним выпуском исправить выбор нативных архивов и подсказку ASR, затем перенести управление расходом токенов, безопасный отчёт, субагентов и задания по расписанию.

**Основание:** запрос пользователя и AGENTS.md, раздел «Rikka-Root: правила форка». Исправления и E — отдельные коммиты; один push после локальной компиляции и выбранных unit-тестов; зелёный Daily Build, проверка подписи/nightly, остановка.

Усилить описание нативной работы с /workspace/относительными путями без apt; проверить реальный ZIP roundtrip с ConversationConfig workspace и cwd.

Не менять рабочую отмену/завершение и успешный fallback.
- [ ] Запустить выбранные регрессионные тесты RED/GREEN, компиляцию app; отдельный коммит без push.

## Проект E после согласования объёма

- [ ] Cost guards: выключенная опция cost_guards, nullable soft/hard caps в Assistant, caller-bound check_token_usage. Считать безопасно в Long, ограничивать новые запросы и output maxTokens, прекращать продолжение при hard cap. Субагенты расходуют общий бюджет родителя. Поздние метрики провайдера могут дать превышение в пределах одного уже отправленного запроса; не обещать точную границу биллинга.
- [ ] Reliability: только generate_bug_report. Экспортировать разрешённые поля версии/системы, коды ошибок и очищенные stack frames. Не включать произвольный logcat, диалоги, настройки, ключи, пароли, команды или их вывод. Тест с короткими/нетипичными секретами.
- [ ] Headless: доверенный контекст запуска задаёт владельца, effective ConversationConfig, модель, разрешённые инструменты, предел шагов/времени, бюджет и происхождение веб-контента. Отсутствие UI не выдаёт права: проверять свежие YOLO/Always/допустимые grants, обязательные подтверждения и Android-доступ. Не открывать формы/разрешения автоматически. RootCommandGuard и checkpoint выполнения остаются обязательными.
- [ ] Subagents: отдельный side-context, модель по model_id при dispatch, атомарное ограничение параллельности, наблюдение/отмена только владельцем. Не переключать выбранного ассистента приложения. Отмена/таймаут прекращают сам генератор, а не только ожидание.
- [ ] Cron: Room с безопасной additive migration; неизменяемый идентификатор occurrence и атомарный claim предотвращают повтор побочных эффектов после прерывания. Правдивые success/failed/blocked/indeterminate outcomes; ограниченная история. WorkManager восстанавливает расписание после перезагрузки; boot receiver только переустанавливает план. Приблизительное время запуска без exact alarms. Фоновая работа ограничена допустимым временем worker.
- [ ] Cron tools: schedule_job/list_jobs/get_job_history/delete_job/pause_job/resume_job/trigger_job_now. Текущий ассистент/владелец, проверка включённой функции перед каждым запуском. Прямые действия проходят ту же политику инструмента, что LLM-вызовы.
- [ ] Интеграция: точные @SerialName Agent, опции выключены по умолчанию, все чтения личных данных/изменения в ToolPermissionPolicy, русские настройки и ошибки.

## Разрешения

Ожидается новое обычное RECEIVE_BOOT_COMPLETED; уведомления используют существующий POST_NOTIFICATIONS. Спецдоступы, READ_LOGS, exact alarms и исключения из оптимизации батареи не требуются. Секреты не добавляются в БД/отчёты/бэкапы.

## Проверки и выпуск

- [ ] Бюджет: переполнение Long, нулевые/невалидные лимиты, stop-before-next-request, конкурентные дети и отмена.
- [ ] Headless: запрещённая root-команда, обязательное подтверждение, отозванный grant/Android-доступ, веб-контент и отключение функции.
- [ ] Субагенты: неизвестная/неоднозначная модель, чужой run ID, атомарная параллельность, изоляция контекста, остановка настоящей генерации.
- [ ] Cron: часовой пояс/DST, reboot/catchup, process interruption без повтора побочного эффекта, лимиты запусков, отмена/ошибка/ожидание одобрения и миграция.
- [ ] Отчёт: содержимое не включает переданные секреты, сообщения, настройки или произвольные логи.
- [ ] Локально только затронутая компиляция и выбранные unit-тесты. Один финальный push, CI тесты/lint, исходная подпись и nightly SHA/APK, общий отчёт и остановка после E.
