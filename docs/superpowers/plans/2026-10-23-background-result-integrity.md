# Сохранение диагностики фоновых вызовов

**Цель:** доработать текущий личный форк без перехода на upstream 3.x. Сохранить фактический вывод неуспешных Root-вызовов до потребителя результата фоновой задачи и в ограниченной сводке workflow.

**Основание:** пользователь ранее потребовал сохранять stdout/stderr/exit_code и реальные статусы, затем поручил продолжить исправления нашего форка. Рабочая ветка `ccr-e93188a6-grrqko`, исходный commit `44f82cd3217277d4a78a90233d7d85d04c6cf03a`.

**Подход:** сохранить уже полученный Text-результат при остановке HeadlessTaskRunner из-за фактической ошибки инструмента; включать вывод завершившегося неуспешного действия в существующую сводку WorkflowActionRunner. Новые хранилища, схемы, инструменты, разрешения и нормализация команд не нужны. ErrorCode остаётся собственным кодом из существующего whitelist; Root-журнал и cron-история сохраняют прежний состав данных. Для workflow сохраняются лимиты 200 символов на действие и 2000 на всю сводку, включая ранние возвраты.

## Границы

Лимиты шагов сейчас не являются целью пользователя. Остальные части Root, памяти, UI и базы без подтверждённой регрессии не менять. Секреты и бэкапы не читать. Новые ключи подписи, PR и стабильные релизы не создавать. Обычные команды, пробелы, кавычки и перенаправления передавать без правок. Фоновая задача после ошибки остаётся FAILED/BLOCKED/INDETERMINATE; следующие действия не выполняются.

## Review focus

Проверить: команды с частичным эффектом не повторяются; успешные error-shaped данные остаются данными; no_result не сохраняет тело; cron/root-журнал не получает raw stdout/stderr; timeout/отмена сохраняют правильное состояние; сокращение сводки не разрывает surrogate pairs и всегда отмечено.
