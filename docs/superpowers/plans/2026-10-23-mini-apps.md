# Mini apps compatible with Moru

Source of behavior: user request «реализуем так же как в mora, мини приложения»;
Moru `2101b5e457031d8adb1098dac880bdbb3019623f`, releases 0.1.34–0.1.37 and
`lib/core/services/mini_apps`, `lib/features/mini_apps`, workspace publish/data tools.

## Scope and constraints

Implement the full current mini-app flow in Kotlin: workspace publishing, isolated
JSON storage, catalog, standalone viewer, home shortcuts, AI/notifications/reminders,
manifest-scoped fetch/calendar, safe `.moruapp` import/export, data tool, and an
isolated hidden publication check. Preserve `moru-app.json`, `.moruapp`, `window.moru`
and their method/argument semantics. Own chat links are `rikkahub://app/<id>`.
No Root access or provider credentials are exposed through the bridge. Keep existing
chat design and app ID. No local APK build; affected compilation/tests, then existing
signed Daily Build workflow. All integration changes remain in one <=60-file packet.

The reference is behavioral, not copied Dart. New Kotlin sources cite the pinned
reference; document necessary Android adaptations. Use native Android permission
prompts at first use; no new special access. Hidden checks copy installed data and
stub AI, notifications, reminders and calendar writes.

## Shared interfaces

Package `me.rerere.rikkahub.miniapps`. JSON uses kotlinx.serialization.json.

* `data class MiniApp(id: String, name: String, directory: File,
  description: String = "", entry: String = "index.html", icon: String? = null,
  dataHelp: String = "", network: List<String> = emptyList(),
  permissions: Set<String> = emptySet(), updatedAt: Long = 0)`;
  derived `codeDirectory`, `entryFile`, `iconFile`, `link` and `toJson(): JsonObject`.
* `MiniAppException(val code: String, message: String) : Exception(message)`.
* `MiniAppStore(val rootDirectory: File)`; `apps: StateFlow<List<MiniApp>>`,
  `changes: SharedFlow<MiniAppStorageChange>` (appId, key); `suspend load()`;
  `byId(id): MiniApp?`; suspend `install(source: File): MiniAppInstallResult`
  (app, updated, files, bytes), `delete(id)`, `refreshBridge(app)`,
  `storageGet(id,key): JsonElement`, `storageSet(id,key,value,fromApp=false)`,
  `storageRemove(id,key,fromApp=false)`, `storageKeys(id): List<String>`,
  `storageAll(id): JsonObject`, `readReminders(id): JsonObject`,
  `writeReminders(id,JsonObject)`, `exportArchive(id,withData,into): File`,
  `importArchive(file): MiniAppImportResult` (app, updated, dataRestored).
  `addDeleteHook(suspend (String)->Unit)`. Companion constants and
  `linkFor(id)`, `idFromLink(link)`, `allowsHost(app,host)`.
* `MiniAppBridgeScript.source`: the compatible `moru.js` bridge script.
* `MiniAppHost` with optional suspend callbacks `ask: (String,String?)->String`,
  `notify: (String,String)->Unit`, `calendar: (String,JsonObject)->JsonObject`,
  optional `reminders: MiniAppReminders`, `fetch: MiniAppFetch`, and native-only
  `beforeReminderSet` first-use permission callback.
* `MiniAppBridge(store,appId,host=MiniAppHost())`: suspend `handle(String): String?`,
  `pageErrors`, `failedCalls`; companion `changedScript(key)`, `MAX_PROBLEMS=50`.
* `MiniAppFetch(client: OkHttpClient = OkHttpClient())`: suspend
  `fetch(app,args: JsonObject): JsonObject`.
* `MiniAppReminders(store, schedule: suspend (MiniAppReminderOccurrence)->Unit,
  cancel: suspend (Int)->Unit)`: suspend set(appId,id,JsonElement), remove,
  list(): JsonObject, cancelAll; normalized reminders and stable notification IDs.
  Occurrence fields id,appId,title,body,hour,minute,weekday:Int?.
* `MiniAppCheckReport(loaded,pageErrors,console,failedCalls,visibleContent)` with
  `toJson()`; `MiniAppChecker(context,store,fetch=MiniAppFetch()).run(app)` suspend.
* `MiniAppWebSession(context,app,bridge,onLoading,onExternalLink)` created on Main,
  exposes `webView: WebView`, `load()`, `close()`. Viewer/checker share this engine.
  Serve only the installed app directory through a dedicated HTTPS asset origin;
  origin-bound main-frame message listener implements MoruBridge. External top-level
  navigation leaves the viewer; no JS interface on arbitrary browser pages.

## Task 1: Store and archives

Own MiniApp.kt, MiniAppStore.kt and store/archive unit tests. Match reference limits,
manifest validation, recursive excludes, bridge injection, persistent update data,
serialized atomic JSON mutations, catalog reload, and archive format. Reject path
traversal/symlinks and enforce bounds on actual bytes. Preserve the old installation
on failed publication. Store filesystem work runs on IO. Use the shared interfaces.
Write and run meaningful targeted tests before/after implementation; coordinate
Gradle with the controller. Do not commit/push independently.

## Task 2: Bridge, fetch and reminder definitions

Own MiniAppBridge.kt, MiniAppBridgeScript.kt, MiniAppFetch.kt, MiniAppReminders.kt
and corresponding tests. Port the pinned source protocol and limits literally,
including asynchronous error replies, busy AI guard, event notifications, validated
network redirects and bounded streams, reminder normalization/max20/stable IDs.
Use a dedicated HTTP client without app/provider cookies. Preserve coroutine
cancellation; avoid swallowing cancellation as a normal JS error. Shared store API
is Task 1. No Android scheduler/permissions here. Do not commit/push independently.

## Task 3: Web runtime and publication check

Own MiniAppWebSession.kt, MiniAppChecker.kt and runtime/check tests. Shared signatures
above; read the source checker, sandbox and page. Use the same runtime for live and
hidden checks. Capture JS/resource errors and console warnings; 15s load timeout,
2s settle, visible-content count; checker uses a throwaway installation copy,
inert device/model hosts, real bounded allowlisted fetch. Stop timers/destroy
WebViews and delete sandbox in finally including cancellation. Visible UI/Activity
and Android manifest are controller-owned. No independent commit/push.

## Task 4: Agent tools and permissions

Own MiniAppTools.kt (publish helper and data tool), WorkspaceTools.kt,
LocalToolOption.kt, LocalTools.kt, local tool presentation/permission mappings and
workspace tool settings. Integrate publish_mini_app for selected ready workspaces

with list/read/write/remove and bounded all-data read. Register ordinary permissions
and stable @SerialName. Keep declarations/descriptions compatible with Moru,
Russian UI. Source directory must resolve via WorkspaceRepository, honoring mounts.
Use Koin for store/checker if needed, preserving existing constructors/tests. New
strings should be reported to controller, who owns all resource XML. No route/DI
edits or independent commit/push. Write targeted tool/permission tests.

## Task 5: Native host, catalog and integration (controller)

Build catalog with open/pin/share/delete/import, data-inclusion choice and confirmed
deletion. Add settings/search route and mini-app link handling without changing chat
layout. Standalone viewer owns WebView lifecycle, reload, Back history and pin.
Native host selects current assistant chat model with default fallback, text-only
one-shot request; calendar functions reuse native calendar operations behind a
first-use permission prompt. Notifications open the app. Persist/reschedule daily
or weekday reminders across reboot/time/timezone changes; exact if already allowed,
otherwise inexact. Removal cancels reminders. Import via SAF and Android open/share;
export unique immutable cache snapshot. Render SVG/fallback shortcut icons. Register
DI and Android components. Add keys to all six required locale catalogs.
