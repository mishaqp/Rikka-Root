# Интерфейс инструментов ассистента

Задача пользователя от 11 октября 2026 года: заменить длинный список инструментов категориями, поиском, пресетами и листами настроек. Это самостоятельная разработка интерфейса, а не перенос из Agent. Выполнение и один push разрешены в исходном запросе.

## Границы

- Не менять LocalToolOption, SerialName, Assistant, ConversationConfig, форматы настроек и бэкапов.
- Использовать реальные фабрики функций только для метаданных; не выполнять инструменты при открытии настроек.
- Сохранить запросы Android при включении, режимы одобрений, HARDLINE и существующие дополнительные настройки.
- В текущей модели 55 вариантов, и список пользователя также содержит 55. Счётчики вычисляются по реестру.

## Реализация

1. Единый реестр девяти категорий, иконок, описаний и пресетов. Проверка полноты через sealedSubclasses.
2. Главный экран: число включённых, оценка описаний/JSON-схем/выбранных навыков, поиск, переносимые по строкам чипы и категории. Пресеты подтверждаются с перечнем изменений.
3. Категория: общий переключатель и компактные строки. Детали открываются в ModalBottomSheet с функциями, доступами Android, текущими одобрениями и прежними настройками.
4. Единый последовательный UI-контроллер запросов Android. Поздние ответы привязаны к ассистенту и поколению очереди; изменения сливаются с актуальными настройками.
5. Экран одобрений использует тот же реестр и поиск; переход из деталей фокусирует соответствующую функцию.

## Проверки и выпуск

- Локально: compileDebugKotlin, compileDebugJavaWithJavac, unit-тесты новых UI-классов и затронутых путей разрешений/одобрений.
- Независимая проверка диффа, сохранения настроек и отсутствия побочных эффектов у метаданных.
- Коммиты после проверок, один push в ccr-e93188a6-grrqko.
- Дождаться Daily Build, проверить полный набор тестов, отсутствие новых lint-ошибок относительно принятой сборки и APK nightly с подписью форка.
- Отчёт с описанием экранов и проверками на телефоне; затем остановка.
