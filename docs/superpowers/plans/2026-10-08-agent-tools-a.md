# Перенос инструментов Agent: пакет A

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Один коммит и push после проверок всего пакета, согласно запросу пользователя.

**Goal:** Перенести сведения об устройстве и системный вывод в Rikka-Root, сохранив выключенное состояние новых функций и систему одобрений форка.

**Architecture:** Новые варианты в существующем `LocalToolOption`, реализации в `data/ai/tools/local`, регистрация в `LocalTools`. `ChatToolFactory` сохраняет существующее чтение эффективного ассистента и передаёт идентификатор чата для уведомлений; `ConversationConfig` не меняется.

**Tech Stack:** Kotlin, Android API 26+, Compose, kotlinx.serialization, JUnit.

**Spec:** Запрос пользователя о пакетах A–G; согласование разрешений пакета A в текущей сессии. Образец: `/workspace/refs/rikkahub-agent`, ExTV/rikkahub-agent. Этот файл фиксирует требования пакета A.

## Global Constraints

- Только пакет A; после зелёного Daily Build остановиться до «дальше».
- Ветка `ccr-e93188a6-grrqko`; PR не создавать. Менее 40 изменённых файлов.

- Чтение сведений A без одобрения; `show_toast`, `post_notification`, `share` через общую систему одобрений; share открывает системное меню выбора.
- Все новые функции выключены по умолчанию. Интерфейс на русском.
- Опасные разрешения запрашиваются при включении своей функции; отказ оставляет функцию выключенной и выводит понятное сообщение. Повторные вызовы после отзыва разрешений возвращают ошибку вместо падения.
- Новые разрешения: READ_PHONE_STATE, ACCESS_NETWORK_STATE, ACCESS_FINE_LOCATION, ACTIVITY_RECOGNITION; ACCESS_COARSE_LOCATION запрашивается вместе с точной геолокацией по требованиям Android 12+. POST_NOTIFICATIONS уже объявлено.

- Сохранять имеющиеся авторские заголовки Agent; не добавлять секреты и не выводить личные данные в логи.
- Локально только компиляция app и unit-тесты затронутых классов. APK только Daily Build; дождаться run именно для нового SHA.

## Review Focus

- Отзыв разрешения после включения или импорт настроек без разрешений: понятная ошибка, без падения и автоматического запроса.
- Wi-Fi с отключённой геолокацией/скрытыми SSID: подключение не становится ложным «disconnected».
- Отмена чтения датчика и отсутствие событий: listener закрывается, пустые значения не выдаются за успех.
- Уведомления из разных чатов и после перезапуска: нажатие открывает правильный чат; отдельные уведомления не получают одинаковый автоматически выбранный ID.
- Root-команда не принимает произвольный пакет или разрешение; отказ su и частичная выдача не включают функцию.
