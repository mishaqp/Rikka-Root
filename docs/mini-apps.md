# Мини-приложения

Поведение перенесено из [Moru](https://github.com/mishaqp/Moru/tree/2101b5e457031d8adb1098dac880bdbb3019623f),
версия исходников `2101b5e457031d8adb1098dac880bdbb3019623f`, возможности выпусков
0.1.34–0.1.37. Реализация Android — Kotlin; формат `.moruapp`, манифест
`moru-app.json` и JavaScript API `window.moru` совместимы с Moru.

## Использование

Выберите готовую рабочую среду в чате и попросите ассистента создать приложение.
Он сохраняет статические HTML/CSS/JS и `moru-app.json` в папке среды, затем вызывает
`publish_mini_app`. Ссылка `rikkahub://app/<id>` открывает приложение в отдельном
окне. Оно также доступно в настройках → «Мои приложения»: открыть, добавить ярлык,
поделиться, импортировать или удалить. Обновление с тем же `id` сохраняет записи
пользователя и определения напоминаний.

Пример манифеста:

```json
{
  "id": "water-tracker",
  "name": "Вода",
  "description": "Дневник воды",
  "entry": "index.html",
  "icon": "icon.svg",
  "data": "Ключ glasses: массив {at: ISO-8601, ml: number}.",
  "network": ["api.example.com"],
  "permissions": ["calendar"]
}
```

`entry` по умолчанию — `index.html`; `icon`, `data`, `network` и `permissions`
необязательны. Сервер приложению не нужен. Хост подключает `moru.js` сам.

```javascript
const glasses = (await moru.storage.get('glasses')) || [];
await moru.storage.set('glasses', [...glasses, {at: new Date().toISOString(), ml: 250}]);
window.addEventListener('moru:storage', () => redraw());

const answer = await moru.ai.ask('Предложи короткое напоминание', {system: 'Ответь одной строкой'});
await moru.notify('Вода', answer);
await moru.reminders.set('drink', {time: '09:30', days: [1, 2, 3, 4, 5], title: 'Вода', body: 'Пора выпить воды'});
```

Также доступны `storage.remove/keys`, `app.info`, `reminders.remove/list`,
`moru.fetch(url, {method, headers, body})`, `calendar.list(query)` и
`calendar.add(event)`. Модель берётся из настроек текущего ассистента с запасным
выбором модели по умолчанию; в запрос идут только переданные `system` и `prompt`.
История чатов и ключи провайдеров в мини-приложение не передаются.

Для изменения записей из чата включите инструмент ассистента «Мини-приложения».
Инструмент `mini_apps` сначала перечисляет приложения, описание формата и ключи,
потом читает или меняет данные. Открытое приложение получает событие `moru:storage`.
Обычные разрешения инструментов и индивидуальные настройки публикации рабочей
среды продолжают действовать.

Уведомления и календарь запрашивают обычные разрешения Android при первом
использовании. Напоминания сохраняются на диске и восстанавливаются после
перезапуска устройства, обновления приложения и смены времени/пояса. При уже
предоставленном доступе к точным будильникам используется точное время; иначе
Android может отложить напоминание. Нового специального доступа нет.

Экспорт предлагает приложение без записей или вместе с ними; напоминания не
экспортируются. Импорт восстанавливает вложенные данные только в пустое хранилище.
Существующие записи не заменяются. Каждый файл для отправки — отдельный снимок.

## Проверка публикации и границы

После установки выполняется скрытый запуск на отдельной копии приложения и его
данных: ошибки JavaScript и ресурсов, предупреждения консоли, неуспешные вызовы API
и пустая страница попадают в `check` результата инструмента. Запросы к модели,
уведомления, напоминания и календарь при этой проверке подменены; реальные данные
не меняются. Вызовы `moru.fetch` остаются ограниченными манифестом. Если WebView
недоступен или проверка прервана, успешная установка сохраняется, но инструмент
возвращает явный отчёт `check` с требованием проверить приложение вручную.

Как в Moru: до 500 файлов и 20 МиБ исходного кода, до 5 МиБ JSON-данных,
20 напоминаний и 20 разрешённых сетевых имён на приложение. `moru.fetch` допускает
HTTP(S), запрос до 1 МиБ и ответ до 2 МиБ, проверяет каждый редирект; ожидание
одного запроса — 20 секунд. `*.example.org` включает сам домен и его поддомены.
Календарь требует `"permissions": ["calendar"]`. Root, оболочка, произвольные
файлы рабочей среды и секреты приложения через JS-мост недоступны.

Нативные адаптации: собственная схема ссылок; отдельный HTTPS-origin для каждой
установки вместо `file://`; сообщения только от главного фрейма этого origin;
ответы моста привязаны к документу и не попадают в новую страницу после перезагрузки;
атомарное обновление с откатом; ограничение фактических байтов при распаковке;
генерируемая вставка моста исключается из экспорта, чтобы приложение на границе
20 МиБ можно было импортировать повторно. Код и данные на диске обслуживаются
вне потока интерфейса.
Восстановление и доставка напоминаний согласованы с их изменением и удалением
приложения, чтобы старое расписание не заменяло новое.

## Что проверить на телефоне

1. Создать трекер, добавить записи, закрыть приложение и открыть снова; обновить
   с тем же ID и проверить сохранение записей.
2. Изменить запись инструментом `mini_apps`, пока приложение открыто, и проверить
   перерисовку. Добавить ярлык, закрыть Rikka-Root и запустить приложение с ярлыка.
3. Разрешить уведомления, поставить ближайшее напоминание и проверить доставку
   с закрытым окном. При необходимости проверить восстановление после перезагрузки.
4. Экспортировать с данными и без них; импортировать файл из системного проводника
   и через «Поделиться». Проверить сохранение существующих записей при обновлении.
5. Проверить запрос модели и календарь, включая отказ в разрешении. Реальное
   выполнение Chromium и поведение конкретного рабочего стола требуют устройства.
